- 所有业务表以 `user_id` 挂在 `user` 下 → 多用户隔离

## 五、制作流程：一步一步怎么做

### 阶段 0：需求与规划（第 1 天）

1. **明确目标**：不是"做个网站"，而是"做一个能放进求职作品集的 Java 后端项目"。
2. **写需求文档**（可参考 docs/TECH_STACK_NOTES.md 与 README）：确定功能边界——为 JLPT N3-N5 备考者做：注册登录、背单词、五十音、测验、错题本、打卡、SRS 复习、统计、模拟考试。
3. **定技术栈**（见上表）。
4. **定目录结构**：前后端分离 `backend/frontend`（本仓库合并为 src + frontend）。

### 阶段 1：环境准备（第 1-2 天）

1. 本机已有 macOS + JDK 17（Corretto）。注意项目要求 **Java 17**（不是新装的 Java 26），IDEA 里 Project SDK 选 17。
2. MySQL 用本地 3307 端口（避开系统占用），Redis 6379。
3. 用浏览器访问 `https://start.spring.io` 生成 Spring Boot 3.4.1 骨架工程，解压后导入 IDEA（依赖：Web、MyBatis、MySQL、Redis、Lombok、Security Crypto 等，见 pom.xml）。
4. 配置 Maven 仓库与 wrapper（mvnw 已入库，CI 可用）。

### 阶段 2：建库建表（第 2 天）

1. 建库：`CREATE DATABASE japanese_learning DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
   - **关键**：必须 utf8mb4，否则日文汉字/假名/emoji 乱码。
2. 建表策略：**先 9 张核心表**（user/word/question/question_option/answer_record/wrong_book/word_memory/study_progress/daily_checkin，见 `sql/init_tables.sql`），后面随模块再补（SRS 加 word_review、考试加 exam_record/exam_answer、统计加 daily_stats、五十音加 kana_progress）。
3. 建表要点：外键命名规范 `fk_表_关联表`；联合唯一键防重复（如打卡 uk_checkin(user_id,checkin_date)）；时间戳默认 CURRENT_TIMESTAMP。
4. 种子数据：单词按 N5/N4/N3 分文件（seed_words_n5_more.sql / n4 / n3），用 CSV/脚本整理 1377 条；题库 120 题由 JLPT 真题风格题目整理（seed_questions_jlpt.sql），选项单独表存。
5. **踩坑**：word 表曾出现双重编码乱码（latin1 混入 utf8mb4），修复 = SQL 还原正确字符 + 清 Redis 缓存（`word:*`）。

### 阶段 3：后端骨架（第 2-3 天）

1. `application.yml` 全部环境变量化：`${MYSQL_URL:...}` `${MYSQL_USER:root}` `${REDIS_HOST:localhost}` 等，本地有默认值、云端注入覆盖。
2. 配置 MyBatis：`map-underscore-to-camel-case: true`（数据库下划线 → Java 驼峰）。
3. 统一返回体 `Result<T>`（code/message/data）+ 分页 `PageResult<T>`。
4. 全局异常处理器：业务异常转友好文案、其余转 500 JSON。
5. **开发节奏**：每写完一层（Entity→Mapper→Service→Controller）立刻 `mvn compile`，报红就地修，不要攒代码。

### 阶段 4：按模块分层实现（第 3 周 ~ 第 4 周）

每个模块统一套路：**建表（如需）→ Entity → Mapper → Service → Controller → Swagger 验证 → 前端页面**。

| 模块 | 后端要点 | 前端页面 |
|---|---|---|
| 用户认证 | JWT 签发/校验（jjwt 0.12.6）、BCrypt 存密码、拦截器排除白名单 | index.html 登录/注册 |
| 单词 | 分页 list、详情、按等级筛选；`word/*` Redis 缓存 | word.js 背词卡片 |
| 五十音 | /api/kana/list 数据 + /test 自测 | kana.js 平/片假名对照练习 |
| 测验 | /api/question/random **随机抽题**（去重算法） | quiz.js 组卷作答 |
| 答题记录 | /api/record/submit 写 answer_record；答错自动插入错题本 | 测验流程内联 |
| 错题本 | /api/wrong/list + /master 标记已掌握 | wrong.js 错题列表重做 |
| SRS 复习 | /api/review/due 到期队列 + /submit 按 **SM-2** 更新（repetitions/interval/due_date） | 背词页"到期复习" |
| 打卡 | /api/checkin/today 判重（唯一键）、/month 日历、/stats 连续天数 | checkin.js |
| 模拟考试 | /api/exam/submit 判分（文字語彙/文法/読解分项分）、/records、/stats | exam.js 计时答题 |
| Dashboard | /api/dashboard/stats 聚合查询 | app.html 首页仪表盘 |
| 学习进度 | study_progress 通用进度记录 | — |

**关键算法实现**：
- 随机组卷：`SELECT ... ORDER BY RAND() LIMIT n` 或按 level/type 加权抽样
- SM-2 间隔重复：每次复习反馈（重来/困难/良好/简单）→ `repetitions++`、间隔按 1/2/4/7/15 天指数增长、`due_date = today + interval`
- 连续打卡：按日期差判断连续区间

### 阶段 5：前端开发（第 4 周）

1. 纯静态 HTML/CSS/JS（ES Module），`localStorage` 存 token。
2. `api.js` 统一封装 fetch：自动带 `Authorization: Bearer <token>`，401 跳登录。
3. 模块化 js：auth/word/quiz/exam/kana/checkin/wrong/review/ai/app。
4. 页面用语义化 section 切换（hash 或按钮显隐），无路由库。
5. CSS 一个 style.css 全站共用（1673 行）。
6. 联调：本地 `python3 -m http.server 3000` 开前端 → fetch `http://localhost:8080/api`。

### 阶段 6：Docker 化（第 4 周末）

1. 写 `Dockerfile`：Maven 多阶段构建（maven:3.9-eclipse-temurin-17 编译 → eclipse-temurin:17-jre 运行）。
2. 写 `docker-compose.yml`：mysql(3308) + redis(6380) + backend(8080) 三容器，backend 通过环境变量连容器内 mysql/redis。
3. `docker initdb` 目录放初始化 SQL。
4. 一键验证：`docker compose up -d --build` + 导入 SQL。

### 阶段 7：上线（零成本方案，第 5 周）

1. **前端**：推 Hugging Face Static Space `nay20024-japanese-frontend`（免费静态托管），线上地址 https://nay20024-japanese-frontend.static.hf.space
2. **后端公网**：无法免费上云（用户网络下各云平台均不可用/需信用卡）→ 用 **localhost.run 免费 SSH 隧道** 暴露本机后端：`ssh -R 80:localhost:8080 nokey@localhost.run`
3. **保活**：写 `jp_tunnel_watch.sh` + launchd plist（RunAtLoad + StartInterval=45 秒），自动探测 URL、断连重启、URL 漂移后自动改写镜像 api.js 并推 HF（sync_frontend.py）。
4. **坑**：隧道 URL 每次漂移、免费服务端不稳定（503）→ 只作为临时演示；已决定赴日后做后端上云正式迁移。

### 阶段 8：AI 助手扩展（第 6 周，收尾镀金）

1. pom 加 `spring-ai-openai-spring-boot-starter` 1.0.0-M6（Spring Boot 3.4.1 兼容）；**CI 需显式加 spring-milestones 仓库**。
2. application.yml 配 `base-url: https://api.deepseek.com`、`model: deepseek-chat`、`api-key: ${DEEPSEEK_API_KEY}`（只环境变量，不入 git）。
3. 三个单次问答：错题解析（传 questionId 自动拼题库题干/选项/答案，要求固定小节输出）、单词例句（拼词库词义做上下文）、语法问答。
4. 连续对话：`POST /api/ai/chat/stream`（SSE）+ `SseEmitter` + `ChatModel.stream` 逐字增量推送；Redis `ai:chat:{sessionId}` 存最近 20 条（约 10 轮）TTL 7 天；会话识别 JWT userId（登录）或 X-Chat-Session（游客，响应头下发）。
5. 前端 ai.js 聊天界面：fetch 读 ReadableStream、按 `\n\n` 切 SSE、打字机渲染；`[DONE]`/`[ERROR]` 协议处理。
6. 三个原功能降为快捷按钮，填入提问模板。

### 阶段 9：文档、GitHub、CI（收尾）

1. README.md：功能表/架构图/快速开始/在线演示/环境变量/目录结构/截图/核心设计（已更新到含 AI）。

## 七、值得在面试里讲的点

1. **JWT 无状态认证 + BCrypt**：拦截器统一校验，前端 localStorage 携带。
2. **Redis 缓存与一致性**：单词热点缓存 `word:*`，数据修复后清缓存。
3. **SM-2 间隔重复算法**：背单词不是"随机重来"，是按遗忘曲线调度复习。
4. **随机组卷与分项判分**：模拟考试按 JLPT 结构出分。
5. **SSE 流式 + 多轮记忆**：SseEmitter、Reactor 订阅、超时/断连 dispose、Redis 会话裁剪。
6. **Spring AI 模型抽象**：面向 ChatModel 编程，可换厂商。
7. **云原生工程化**：环境变量化、Docker Compose、CI（GitHub Actions + MySQL service）、Swagger。
8. **踩坑复盘**：编码乱码、隧道漂移、CI 缺仓库/缺客户端——都是真实工程问题的解决过程。
